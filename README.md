# 0km 이어달리기 (Heart Race)

《ㅊㅊㅊ 운동회》(2026.08.22, 서울 마포 누부크)의 **³ 신체 운동 — 0km 이어달리기**
세션에서 쓰는 호스트 웹과 참가자 앱입니다. 기획·운영 @livinglikeagiraffe_,
공간 @nuvook_.

운동회 자체가 "몸을 움직이는 운동뿐 아니라 생각하고, 감각하고, 마음을 움직이는
행위 모두를 '운동'으로 보는" 자리이고, "'경쟁과 승패'보다는 함께 움직이며
생각하고 느끼는" 것을 지향합니다. 화면 문구와 위계도 이 방향에 맞춥니다.

아무도 실제로 달리지 않지만, 참가자의 심장이 달리는 참여형 운동회입니다. 관람자는 자신의 휴대폰 카메라와 플래시에 손가락을 올려 심박을 측정하고, 검출된 **박동 한 번마다 정확히 한 걸음** 전진합니다. 먼저 정해진 박동 수에 도달한 심장이 우승합니다.

이 작품은 원래 심박수가 높은 사람의 우위를 보정하지 않습니다. 참가자가 호흡, 긴장, 움직임 등으로 자기 심박을 조절해 경주하는 행위 자체가 작품의 내용입니다. 공정성 보정 대신 모든 참가자에게 같은 규칙을 적용합니다.

## 현재 구현

- 호스트 웹: 방 생성, 4자리 코드와 QR, 참가자/측정 상태, 경기장 입장 후 트랙 위에서 출발, 트랙에 겹쳐지는 3초 카운트다운, 실시간 경주와 좌측 순위표, 헤더를 감추는 전시 모드(`H`), 운영자 경기 종료, 최고 심박수 순위, 재경기
- iOS·Android 앱: 방 입장, 닉네임, 명시적인 측정 시작, 카메라·플래시 상태와 원형 미리보기, 손가락 안내, 첫 측정 완료, 대형 실시간 BPM, 경기 진행률과 결과
- PPG 처리: RGB 프레임의 중앙 ROI 샘플링, 색 정규화, 0.45–4Hz 대역 통과, 적응형 피크 검출, IBI 중앙값 기반 BPM, 신호 품질·신뢰도 판정
- 브랜드 토큰·타이포그래피·로고 사용: [`docs/brand.md`](docs/brand.md)
- PPG 검증 기준과 공개 데이터 재생: [`docs/ppg-validation.md`](docs/ppg-validation.md)
- 서버: 서버 권위형 Socket.IO 방/경기 상태, 재접속 세션, 박동 중복·역순·저품질·비정상 IBI 거부
- 규칙: 승인된 박동 1회 = 이동 1회. 3·6·9번째 박동은 더 큰 시각·햅틱 피드백만 주며 이동 거리는 늘리지 않음
- 팀 이어달리기: 2~~4팀, 팀별 2~~30명, 주자당 10·20·30·60박동을 선택하고 팀 대표 휴대폰 한 대를 넘기며 5초 동안 바톤 전환
- 팀전 트랙: 주자마다 전체를 달리는 직선 트랙 또는 팀마다 고정 레인을 한 바퀴씩 달리는 원형 트랙
- 팀전 상태와 바톤/PPG 초기화 규칙: [`docs/team-relay.md`](docs/team-relay.md)
- 휴대폰 없는 리허설: 호스트 웹의 `/demo`에서 팀·주자·트랙·박동 수를 설정하면 가상 팀이 자동으로 달립니다.
- 개발용 심박 시뮬레이터: 실제 카메라 없이도 BPM을 조절하며 전체 흐름 테스트

기본 결승선은 60박동이며 한 방에는 최대 8명이 참가할 수 있습니다.

## 구조

```text
apps/host       호스트용 Vite + React 웹
apps/mobile     Expo + React Native 앱 (VisionCamera 네이티브 프레임 처리)
apps/server     Express + Socket.IO 서버
packages/protocol     공유 이벤트·상태 타입
packages/game-engine  서버 권위형 경기 규칙
packages/ppg-core     기기 독립 PPG 신호 처리
scripts/smoke-race.ts 실제 Socket.IO 전체 경기 스모크 테스트
scripts/simulate-hybrid-relay.ts 실제 휴대폰과 가상 팀의 혼합 릴레이 테스트
```

앱과 웹은 모두 Pretendard를 사용하며 큰 숫자 위계를 중심으로 구성했습니다. 호스트 웹의 디자인 토큰은 《ㅊㅊㅊ 운동회》 포스터에서 뽑았습니다 — 잔디 모스 그린 `#9b9443`, 딥 올리브 `#3e3b1b`, 크림 `#fbfbee`. 타이포그래피도 포스터 카드의 위계를 따라 가는 굵기의 큰 영문 카테고리(`PHYSICAL`), 어깨번호 + 한글 세션명, 크림 알약 칩으로 구성했습니다. ㅊㅊㅊ 마크는 포스터 원본에서 배경을 걷어내 `apps/host/public/brand/ccc-logo.png`로 두고 CSS 마스크로 색을 입힙니다. 경기 화면의 트랙만은 따로 지정받은 Spiced Clay(`#bf673c`) 주로와 연둣빛 인필드(`#dceca1`)를 `#e6dad1` 바탕 위에 유지하고, 팀을 구분하는 여섯 레인 색도 채도를 낮춘 채 따로 둡니다. 애니메이션은 상태 설명에만 사용하고 운영체제의 `reduce motion` 설정을 존중합니다.

## 로컬 실행

### 준비

- Node.js 22 이상
- iOS: macOS, Xcode, CocoaPods
- Android: Android Studio/JDK 및 SDK
- 실제 PPG 측정: 카메라와 플래시가 있는 실기기

```bash
npm install
npm run dev
```

호스트 화면은 `http://localhost:5173`, 서버 상태는 `http://localhost:3001/health`에서 확인합니다.

### 실제 휴대폰 연결

Mac과 휴대폰을 같은 Wi-Fi에 연결하고 Mac의 LAN IP를 사용합니다. 예를 들어 Mac이 `192.168.0.20`이라면:

```env
# apps/host/.env.local
VITE_SOCKET_URL=http://192.168.0.20:3001

# apps/mobile/.env
EXPO_PUBLIC_SOCKET_URL=http://192.168.0.20:3001

# apps/server/.env
CORS_ORIGINS=http://192.168.0.20:5173,http://localhost:5173
PORT=3001
```

공유기에서 참가자 간 통신을 차단하는 게스트 Wi-Fi, 사내 방화벽, VPN이 켜져 있으면 연결되지 않을 수 있습니다. 로컬 주소는 같은 네트워크 밖에서는 접근할 수 없습니다.

### 모바일 앱

이 앱은 네이티브 카메라 프레임 프로세서를 사용하므로 Expo Go가 아니라 개발 빌드가 필요합니다.

```bash
npm run prebuild -w @heartrace/mobile
npm run ios -w @heartrace/mobile
# 또는
npm run android -w @heartrace/mobile
```

`개발용 시뮬레이터`를 켜면 카메라 없이 BPM을 ±5씩 조절하며 경기 흐름을 확인할 수 있습니다.

## 검증

```bash
npm run typecheck
npm test
npm run build
```

서버를 실행한 상태에서 전체 실시간 흐름도 검증할 수 있습니다.

```bash
npm run dev:server
# 다른 터미널
npm run smoke
npm run smoke:relay
```

스모크 테스트는 방 생성, 두 참가자 입장/준비, 카운트다운, 각 10박동, 1·2위 확정, 매 3번째 강조를 실제 WebSocket으로 검사합니다. 다른 서버 주소는 `SMOKE_SOCKET_URL`로 지정합니다.

### 휴대폰 1대와 가상 팀의 혼합 경기

일반 팀 이어달리기 방에 실제 휴대폰이 먼저 입장한 뒤, 빈 팀 슬롯을 가상 팀으로
채울 수 있습니다. 가상 팀도 앱과 동일한 참가·측정·박동 이벤트를 보내므로 서버의
바톤 전환, 순위 및 경기 종료 로직은 그대로 사용합니다.

```bash
# 로컬 서버
npm run simulate:hybrid-relay -- ABCD

# 배포 서버
SMOKE_SOCKET_URL=https://socket.example.com \
  npm run simulate:hybrid-relay -- ABCD
```

스크립트 실행 전에 휴대폰 팀이 방에 입장해야 하며, 실행 후에는 호스트 화면에서
경기를 시작합니다. 시뮬레이터 터미널은 경기가 끝날 때까지 열어 둡니다. 예를 들어
4팀 방에 휴대폰 1팀이 들어와 있으면 나머지 3팀을 자동으로 만들고 준비시킵니다.

## 전시 배포 권장안

개인 휴대폰 참여가 목표라면 최종 전시는 다음 구성이 가장 안정적입니다.

1. 앱은 iOS TestFlight/앱스토어와 Google Play 테스트 트랙/스토어를 통해 미리 배포
2. 호스트 웹과 Socket.IO 서버는 전시장과 가까운 리전의 HTTPS/WSS 클라우드에 배포
3. 전시장에는 전용 Wi-Fi, 충전된 대여 기기, 로컬 서버 예비 구성을 준비

개인 휴대폰은 설치와 카메라 권한 단계가 있으므로 입구 QR과 스태프 안내가 필요합니다. 클라우드 WebSocket의 수십~수백 ms 지연은 1초 안팎의 심박 간격보다 충분히 작고, 모든 이동을 서버 수신 이벤트에 맞춰 표시하므로 게임에는 큰 문제가 없습니다. 반면 로컬만 사용하면 인터넷 장애에는 강하지만 같은 Wi-Fi, 게스트 격리 해제, 로컬 IP 설정이 필수이고 관람자 기기 조합에 따른 연결 문제가 생길 수 있습니다. 따라서 **클라우드를 주 경로로, 로컬을 운영 예비 경로로** 두는 구성을 권장합니다.

클라우드 환경 변수:

```env
# host
VITE_SOCKET_URL=https://socket.example.com

# mobile (빌드 시 주입)
EXPO_PUBLIC_SOCKET_URL=https://socket.example.com

# server
CORS_ORIGINS=https://race.example.com
PORT=3001
```

현재 서버의 방 상태는 메모리에 저장됩니다. 단일 전시·단일 서버 인스턴스에는 단순하고 빠른 선택입니다. 여러 서버 인스턴스나 프로세스 재시작 후 복구가 필요해지면 Redis 기반 Socket.IO 어댑터와 방 상태 저장소를 추가해야 합니다.

현재 배포용 주소와 외부 테스터 절차는 [TESTER_GUIDE.md](./TESTER_GUIDE.md)에서 관리합니다.

## 현장 체크리스트

- 전시에 사용할 대표 iPhone·Android 기종에서 플래시 위치, 발열, 프레임 처리량, 손가락 감지 임계값을 사전 보정
- 첫 측정은 최소 5초·유효 박동 4회 뒤 준비 완료로 표시
- 손가락을 너무 세게 누르지 않도록 안내하고, 신호가 약하면 자세를 바꾸도록 즉시 피드백
- 화면 자동 잠금, 저전력 모드, VPN, 알림 방해 요소를 사전에 점검
- 호스트 노트북 유선망, 전용 AP, 대여 기기, 로컬 서버를 장애 대응용으로 준비
- 실제 전시 조건에서 동시 참가 인원과 연속 경기 횟수로 리허설

## 안전·개인정보

이 측정은 작품의 게임 입력이며 의료 진단용이 아닙니다. 원본 카메라 영상은 서버로 보내지 않고 기기 안에서 RGB 요약 신호만 처리합니다. 서버에는 경기 진행에 필요한 닉네임, BPM, 신호 품질, 박동 이벤트만 전송합니다. 전시장 안내문에 카메라 사용 목적과 비의료용임을 명시하고, 불편함이나 어지러움을 느끼면 즉시 참여를 중단하도록 안내하세요.
